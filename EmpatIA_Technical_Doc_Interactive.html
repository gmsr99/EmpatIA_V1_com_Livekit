Estrutura de Dados (PostgreSQL + Pgvector)

users

Contexto Estático

  • id UUID (PK)
  • email TEXT
  • profile JSONB

O campo profile guarda factos estruturados (netos, doenças) injetados no system prompt.

user_memories

Cérebro Vetorial (RAG)

  • content TEXT
  • embedding vector(768)
  • created_at TIMESTAMP

Usado para busca semântica (pgvector cosine similarity). Factos atómicos e episódicos.

session_summaries

Logs & Analytics

  • summary TEXT
  • emotional_state TEXT
  • new_facts JSONB

Trigger para N8N. Base para relatórios semanais enviados à família.

Notas para Desenvolvedores (Gotchas)

⚠️ VAD (Voice Activity Detection) Sensível

O VAD está calibrado para esperar 1 segundo de silêncio antes de considerar que o idoso terminou a frase. Ruídos de fundo constantes (como TV) podem impedir o modelo de responder. Testar em ambiente silencioso primeiro.

👷 Logging Assíncrono

Evita usar print() padrão no backend Python. O LiveKit e o Asyncio podem engolir o output ou misturar threads. Usa a instância de logger fornecida pelo SDK do LiveKit para debug confiável.

🔌 Inicialização do Pgvector

Ao levantar o container do PostgreSQL pela primeira vez, a extensão não está ativa por padrão. É obrigatório correr CREATE EXTENSION vector; na base de dados antes de criar a tabela `user_memories`, caso contrário o tipo `vector(768)` falha.
